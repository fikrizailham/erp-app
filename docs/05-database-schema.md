# Database Schema Reference

Engine: **PostgreSQL 16**. Source of truth: `backend/prisma/schema.prisma` (Prisma ORM).
This document summarizes intent and key constraints per table; see the schema file for exact
types, defaults, and indexes.

## Conventions

- All primary keys are `uuid` (`@default(uuid())`), except lookup-style seed rows which may
  use human-readable ids for seeding convenience.
- All monetary fields are `Decimal(12,2)` or `Decimal(14,2)` — never `Float`, to avoid
  rounding errors in financial data.
- All quantity fields are `Decimal(12,3)` to support fractional units (e.g. grams, liters).
- Enums are Postgres native enums generated by Prisma (`UserRole`, `WarehouseType`,
  `BatchStatus`, etc.) — see the top of `schema.prisma` for the full list.

## Auth & Users

| Table | Purpose | Key fields |
|---|---|---|
| `User` | Staff accounts with a single system role | `email` (unique), `passwordHash` (bcrypt), `role` (enum: ADMIN/MANAGER/PRODUCTION_STAFF/WAREHOUSE_STAFF/CASHIER/SALES/ACCOUNTANT/DRIVER), `isActive` |
| `RefreshToken` | Hashed refresh tokens for JWT rotation | `tokenHash`, `expiresAt`, `revoked` |

## Product & BOM

| Table | Purpose | Key fields |
|---|---|---|
| `Product` | Finished-goods catalog (sellable SKUs) | `sku`, `barcode` (unique), `size`, `sellingPrice`, `shelfLifeDays`, `status` |
| `Recipe` | Versioned BOM per product | `productId`, `version`, `standardYieldQty` |
| `RecipeIngredient` | Line items of a recipe | `recipeId`, `rawMaterialId`, `quantity`, `unit` |

## Raw Materials & Suppliers

| Table | Purpose | Key fields |
|---|---|---|
| `RawMaterial` | Raw material master (fruit, veg, packaging, etc.) | `sku`, `category` (enum), `unit`, `minStockLevel`, `shelfLifeDays` (nullable — null = non-perishable) |
| `Supplier` | Supplier master | `type` (enum: FRUIT/VEGETABLE/PACKAGING/OTHER), `leadTimeDays`, `rating` |
| `SupplierRawMaterial` | Current price per supplier×material | unique on `(supplierId, rawMaterialId)` |
| `PriceHistory` | Append-only price log | `price`, `effectiveDate` |

## Warehouses & Inventory

| Table | Purpose | Key fields |
|---|---|---|
| `Warehouse` | Physical/logical stock location | `type` (enum: RAW_MATERIAL/PRODUCTION/FINISHED_GOODS/OUTLET) |
| `RawMaterialLot` | **Traceability unit for raw materials** — one row per goods-receipt line | `lotNumber` (unique), `quantityReceived`, `quantityRemaining`, `unitCost`, `expiryDate`, links to `Supplier` + `Warehouse` |
| `FinishedGoodsBatch` | **Traceability unit for finished goods** — one row per completed production order | `batchNumber` (unique, format `BLM<YYMMDD><seq>`), `productionDate`, `expiryDate`, `quantityProduced`, `unitCost`, `status` (enum: ACTIVE/EXPIRING_SOON/EXPIRED/DEPLETED/RECALLED) |
| `FinishedGoodsStock` | Quantity of a batch sitting in a warehouse | unique on `(batchId, warehouseId)` |
| `StockMovement` | **Immutable ledger** of every inventory event | `type` (GOODS_RECEIPT/PRODUCTION_ISSUE/PRODUCTION_RECEIPT/TRANSFER/ADJUSTMENT/SALE/WASTE/OPNAME), `itemType`, from/to warehouse, `quantity`, `reference` |
| `StockOpname` / `StockOpnameLine` | Physical count sessions and their variances | `systemQty`, `countedQty`, `variance` |

## Purchasing

| Table | Purpose | Key fields |
|---|---|---|
| `PurchaseRequest` / `PurchaseRequestItem` | Internal request to buy | `status` (DRAFT/SUBMITTED/APPROVED/REJECTED/CONVERTED) |
| `PurchaseOrder` / `PurchaseOrderItem` | Formal order to a supplier | `poNumber` (unique), `status` (DRAFT/SENT/PARTIALLY_RECEIVED/RECEIVED/CANCELLED) |

| Table | Purpose | Key fields |

## Referential integrity highlights

- `FinishedGoodsBatch.productionOrderId` is `@unique` — one order produces exactly one batch
  (partial/split runs are a documented Phase 2 extension, see `10-full-roadmap.md`).
- `SaleItem.batchId` is required (not nullable) — a sale can never be recorded without a
  concrete batch allocation, which is what guarantees receipt-level traceability.
- `RawMaterialLot.goodsReceiptItemId` is `@unique` — 1:1 with the receipt line that created it.
